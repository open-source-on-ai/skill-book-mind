# book-mind 示例与压测用例

本文件配套 SKILL.md（v2.3）使用：第一节为大纲样式唯一对齐基准的完整示例；第二节为索引模式示例；第三节为压测用例（v2.2 原 5 项 + v2.3 新增 3 项，共 8 项）。平台支持知识库时，可将本文件作为示例文件上传。

## 一、标准完整示例（大纲样式唯一对齐基准）

输入：某书第 03 章完整原文（含 3 节、8 个子节，正文此处省略）。

期望输出：

```markdown
## 第03章 LangChain使用之Chains
### 1 Chains的基本使用
#### 1.1 Chain的基本概念
- 链：串联组件形成可复用AI工作流
- 组件连接：组合提示模板、LLM、记忆、工具等
- 工作流：实现复杂任务的模块化执行流程
- 模块化：拆分功能单元，灵活组合调用
- 复杂任务：依靠多组件协作完成高阶需求
#### 1.2 LCEL及其基本构成
- LCEL：LangChain表达式语言，声明式构建流程
- 管道符：使用|串联各个功能组件
- 组件链接：按顺序传递输入与输出数据
- 执行流程：输入→提示模板→模型→解析器
- 声明式：简洁定义AI工作流，无需冗余代码
#### 1.3 Runnable
- 抽象接口：LCEL组件统一遵循的标准协议
- 统一调用：所有组件共用invoke等方法
- 批量处理：batch方法实现批量任务执行
- 流式输出：stream方法逐段返回结果
- 异步调用：ainvoke提供异步执行能力
#### 1.4 使用举例
- 分步调用：逐个执行组件，手动传递结果
- 链式调用：通过管道符一键组装完整链路
- StrOutputParser：通用字符串输出解析器
- 代码示例：提供两种调用方式完整代码
- 效果对比：对比分步与链式写法优劣
### 2 传统Chain的使用
#### 2.1 基础链：LLMChain
- 基础链：传统体系中最原始的链结构
- 弃用提示：0.1.17版本后官方不再推荐
- 单次问答：适用于单轮简单问答场景
- 无记忆：无法自动留存历史对话内容
- 参数配置：支持模型、提示、回调等参数
#### 2.2 顺序链之SimpleSequentialChain
- 顺序执行：多个子链按先后顺序串行运行
- 单入单出：整条链路仅有一组输入输出
- 自动传参：上链输出自动作为下链输入
- 流水线：搭建线性执行的业务流程
- 多链串联：整合多个LLMChain协同工作
#### 2.3 顺序链之SequentialChain
- 多变量：支持多个独立输入、输出变量
- 显式映射：手动指定变量传递对应关系
- 灵活传参：自定义链路间数据流转规则
- 复杂流程：适配多分支、多数据源场景
- 多输入输出：链路可留存多个阶段结果
#### 2.4 数学链 LLMMathChain
- 数学计算：专门处理自然语言数学问题
- 表达式转换：文本问题转为可执行算式
- 代码执行：调用numexpr库运行表达式
- 数值运算：完成加减、乘方等数学计算
- 解析问题：理解自然语言描述的计算题
#### 2.5 路由链 RouterChain
- 动态路由：根据内容自动分配执行子链
- 需求识别：识别用户问题所属业务类型
- 分支选择：匹配对应场景的专属链路
- 子链分发：将请求转发至目标处理链
- 默认链路：设置兜底链处理未知请求
#### 2.6 文档链 StuffDocumentsChain
- 文档合并：把多篇文档内容整合为整体
- 内容填充：将文档塞入提示模板变量中
- 全局理解：模型一次性读取全部文档内容
- 文档摘要：基于合并内容生成简短总结
- 文档问答：依托完整文档解答相关问题
### 3 基于LCEL构建的Chains的类型
#### 3.1 create_sql_query_chain
- SQL链：面向数据库查询的专用链路
- 自然语言转SQL：文本问题自动生成查询语句
- 数据库查询：对接数据库完成数据检索
- 表限定：指定仅使用部分数据表执行查询
- 语句生成：输出标准可执行SQL代码
#### 3.2 create_stuff_documents_chain
- 新版文档链：LCEL风格的文档处理链路
- 文档拼接：整合多篇文档文本内容
- LCEL风格：遵循表达式语言开发规范
- 内容整合：统一处理多份文档信息
- 问答提取：从文档中抽取答案与关键信息
```

## 三、压测用例（8 项，全部通过即可正式上线）

### 用例 1：含「篇」级目录的章节

输入样例：

```text
第一篇 基础篇
第三章 提示工程入门
3.1 提示词的组成
3.1.1 三要素
提示词由指令、上下文、输出格式三部分构成。指令说明模型要执行的任务；上下文提供任务所需的背景信息；输出格式规定回答的结构与样式，使结果稳定可解析。
3.1.2 撰写原则
撰写提示词时应具体、可验证，避免模糊表述；对复杂任务可拆解为多步指令；给出示例能有效约束输出格式。
3.2 Few-shot 示例法
Few-shot 指在提示中加入少量输入输出示例，引导模型模仿示例的格式与风格作答，适用于格式固定、样式敏感的任务。
```

- 上下文：提供任务所需背景信息
- 输出格式：规定回答的结构与样式
#### 1.2 撰写原则

### 用例 5：代码密集章节

输入样例：

```text
第08章 自定义工具开发
8.1 定义一个自定义工具
使用 @tool 装饰器可以把普通 Python 函数注册为 LangChain 工具，函数的 docstring 会作为工具描述传给模型。下面是完整示例：

from langchain.tools import tool

@tool
def search_employee(name: str) -> str:
    """按姓名查询员工信息"""
    query = f"SELECT * FROM employees WHERE name = '{name}'"
    return db.execute(query).fetchone()

print(search_employee.invoke({"name": "张三"}))

8.2 工具参数校验
借助 pydantic 的 BaseModel 为工具定义参数模型，声明字段类型与默认值，LangChain 会在调用前自动完成参数校验与类型转换。
```

期望输出（节选）：

```markdown
## 第08章 自定义工具开发
### 1 定义一个自定义工具
- @tool装饰器：将普通函数注册为工具
- docstring：作为工具描述传递给模型
- search_employee：按姓名查询员工示例工具
### 2 工具参数校验
- pydantic：以BaseModel定义工具参数模型
- 自动校验：调用前完成参数校验与类型转换
```

验证点：API 名（@tool、docstring、search_employee、pydantic、BaseModel）是否一字不差压缩进要点且说明不超过 30 字；是否不保留完整代码块。

## 四、压测结果处理原则

压测任一项失败时，先检查是**规则被执行偏差**（回到封装环节，通常是规范原文被转写，对照 SKILL.md 与 v2.3 定稿逐字校对），还是**规则本身冲突**（此时才需要出 v2.4）。
